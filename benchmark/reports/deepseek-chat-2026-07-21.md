# DeepSeek A/B 量化实验报告（2026-07-21）

## 实验配置

- 模型：`deepseek-chat`
- 每组重复：5 轮
- 并行测试：串行与并行各 5 轮，共 10 次 Agent 任务
- MCP 测试：stdio、Streamable HTTP 各 5 轮，共 10 组发现与调用
- 恢复测试：关闭、开启有限重试各 5 个故障注入任务
- 长上下文测试：5 组，每组包含 1 个原始目标、6 个步骤编号和多轮噪声

复现命令：

```powershell
$env:DEEPSEEK_API_KEY = "<your-key>"
npm run benchmark:deepseek-ab
```

凭据只从环境变量读取，不写入报告或仓库。

## 统计口径

- 并行实验由 DeepSeek 在同一条回复里实际生成三个 Tool Calls。`67.84%` 是工具执行区间收益；
  包含两次模型请求的 Agent 端到端收益为 `12.78%`，两者不能混写。
- MCP 每一组都重新建立真实客户端连接、发现工具，再由 DeepSeek 选择并调用工具。参数合法率通过
  项目的 Tool Registry 按发现到的 JSON Schema 校验。
- 恢复实验为每个工具执行 ID 注入一次瞬时网络故障。关闭重试时每次新执行都会失败；开启后，
  同一个幂等调用在 Registry 内有限重试并恢复。该结果衡量故障注入场景，不等于开放任务整体完成率。
- 漏步骤率比较“仅保留近期窗口”和“摘要 + 独立 Plan”；Token 降幅比较“完整未压缩历史”和
  “压缩历史 + Plan”。这是两个不同基线，不能合并成同一对照口径。
- checkpoint 的回滚、SHA-256 外部修改冲突保护和验证成功提交是确定性安全机制，不依赖模型，
  因此使用 5 轮 × 3 项故障注入检查。

## 简历可引用数据

- 只读工具并行调度：结果一致率 100%，工具执行区间中位耗时降低 67.84%，Agent 端到端耗时降低 12.78%。
- MCP：stdio / Streamable HTTP 共 10 组真实发现与调用，发现、调用及参数 Schema 合法率均为 100%。
- 错误恢复与文件保护：5 组瞬时故障任务完成率由 0% 提升至 100%，checkpoint 与冲突保护通过 15/15 项检查。
- 任务规划与上下文：5 组长任务压力测试中漏步骤率由 100% 降至 0%，目标保持率 100%，平均输入 Token 降低 57.23%。
